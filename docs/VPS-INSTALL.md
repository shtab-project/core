# Установка на VPS по IP

Поддерживается Linux VPS с Ubuntu или Debian и публичным IPv4. Нужен доступ root/sudo.
Обычный файловый хостинг без Docker не подходит. Первый запуск скачивает образы и собирает приложение.
На новом сервере Docker устанавливается из официального подписанного apt-репозитория
([Ubuntu](https://docs.docker.com/engine/install/ubuntu/), [Debian](https://docs.docker.com/engine/install/debian/)).
Существующий Docker не заменяется; для него нужен плагин Compose v2.

## Первый запуск

Загрузите `shtab-vps-install.tar.gz` на VPS, затем:

```bash
sudo mkdir -p /opt/shtab
sudo tar -xzf shtab-vps-install.tar.gz -C /opt/shtab
cd /opt/shtab
sudo bash install.sh --host 203.0.113.10
```

Замените `203.0.113.10` публичным IP своего VPS. Если исходники уже загружены и распакованы,
выполните только последнюю команду из корня проекта.

Установщик создаёт отдельный проект Compose `shtab-vps`, генерирует секреты,
настраивает обратный адрес входа, применяет миграции и ставит «Задачи» и «Заметки».
Версии плагинов и их коммиты закреплены в каталоге ядра.
Первый запуск Authentik может занять несколько минут; установщик ждёт готовности.

Откройте `http://IP_СЕРВЕРА`, нажмите «Войти», используйте `akadmin`.
Пароль сохранён только на VPS:

```bash
sudo cat /opt/shtab/infra/vps/credentials.txt
```

После входа задайте название организации. В настройках первого пользователя появятся права администратора.
Плагины уже установлены и появятся в меню после завершения настройки организации.

Эта установка новая: локальные аккаунты, задачи и заметки с компьютера не переносятся.
Для переноса существующей установки нужен отдельный перенос PostgreSQL, Authentik и секретов.

## Порты и конфигурация

- `80/tcp` — сайт;
- `9000/tcp` — Authentik, необходим для входа;
- PostgreSQL, Redis и API ядра не публикуют порты на хосте.

Разрешите входящие порты `80` и `9000` в панели VPS. SSH оставьте доступным.
Если порты заняты другим сайтом, выберите свободные:

```bash
sudo bash install.sh --host 203.0.113.10 --port 8080 --auth-port 9001
```

Без домена используется HTTP: пароли и данные передаются без шифрования.
Перед регулярной работой подключите домен и HTTPS к сайту и Authentik.

Секреты находятся в `infra/vps/.env`, права файла `600`. Не публикуйте его.
Существующий локальный `infra/.env` не используется и не меняется.
Повторный запуск с тем же IP и портами сохраняет пароли и тома Docker.
Смена IP/портов и обновление уже установленных плагинов не выполняются автоматически.

Подготовить только конфигурацию:

```bash
sudo bash install.sh --host 203.0.113.10 --configure-only
```

## Управление

Команды выполняются из `/opt/shtab`:

```bash
sudo docker compose --env-file infra/vps/.env -f infra/compose.vps.yml ps
sudo docker compose --env-file infra/vps/.env -f infra/compose.vps.yml logs --tail=100
sudo docker compose --env-file infra/vps/.env -f infra/compose.vps.yml restart core web
```

Остановка без удаления данных:

```bash
sudo docker compose --env-file infra/vps/.env -f infra/compose.vps.yml down
```

Не добавляйте `--volumes` / `-v` к `down`: это удалит базу и другие данные.
Для резервной копии сохраните дамп PostgreSQL, весь `infra/vps` и содержимое томов Authentik.
Перед обновлениями делайте резервную копию. Текущий установщик предназначен для новой установки
и повторного запуска той же версии.

Если проверка OIDC не проходит, проверьте IP и порт Authentik: они должны быть доступны
и браузеру пользователя, и контейнеру ядра. Установщик не сообщает об успехе, пока эта проверка не пройдёт.
