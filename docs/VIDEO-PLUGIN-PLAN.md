# Плагин «Видео» — план

Дата: 12 ноября 2026.

Статус: план, реализация не начата. Приоритеты согласованы с пользователем;
порядок реализации и технические детали ниже — рабочие предложения.

## Назначение и приоритеты

Единое рабочее место для видео компании и нескольких каналов на YouTube, VK и Instagram.

1. **Публиковать видео на площадки.**
2. **Автоматически собирать статистику видео в фоне и показывать dashboard.**
3. Позже: анализировать популярные видео, придумывать сюжеты, хранить ассеты
   и генерировать видео из них.

## Первая версия

### Подключение каналов

- Несколько аккаунтов и каналов каждой площадки, с понятными названиями.
- Подключение через официальные механизмы доступа площадок.
- Состояние подключения, доступные возможности и уведомление о необходимости
  заново предоставить доступ.
- Раздельные возможности: чтение статистики и публикация. Отсутствие одной
  возможности не блокирует другую.

### Карточка видео и публикация

- Загрузить готовое видео, указать название, описание и обложку.
- Выбрать площадки и конкретные каналы; при необходимости изменить текст
  и файл для каждой публикации.
- Проверить ограничения формата до отправки.
- Опубликовать сейчас. Публикацию по расписанию добавить следующим шагом,
  после надёжной немедленной публикации.
- Показывать отдельный статус каждой отправки: в очереди, загрузка, обработка,
  опубликовано, ошибка. Ошибка одной площадки не отменяет успешные публикации.
- Сохранять внешние идентификаторы и ссылки; повторять неудачную отправку
  без дублирования уже опубликованных роликов. При неопределённом результате
  сначала сверять состояние с площадкой.
- Добавлять ранее опубликованные видео, чтобы dashboard охватывал существующий контент.

Главная модель: **один ролик → несколько публикаций на разных каналах**.
Статистика принадлежит конкретной публикации; карточка ролика объединяет её результаты.

### Фоновая статистика и dashboard

- Собирать доступные просмотры, лайки, количество комментариев и репосты.
- Дополнительные показатели — охват, сохранения, время просмотра, подписки —
  подключать там, где API и права аккаунта их предоставляют.
- Предлагаемый начальный график: свежие публикации обновлять раз в час,
  старые — раз в сутки; корректировать под квоты и задержки площадок.
- Сохранять историю с датой измерения и периодом отчёта. Различать
  накопительные счётчики, их изменение между замерами и отчёты площадки за период.
- Показывать последние успешные обновления, ошибки и устаревшие данные.
  Недоступный показатель не заменять нулём.
- На dashboard: список каналов, все публикации, результаты за выбранный период,
  динамика и наиболее успешные видео. Фильтры по площадке, каналу и ролику.
- Историю до подключения загружать только там, где её предоставляет API;
  иначе история начинается с первого замера.
- Сохранять определения метрик площадок: общий итог просмотров не считать
  уникальной аудиторией и не приравнивать разные способы подсчёта.

Чтение текстов комментариев и ответы на них — отдельная будущая функция;
для первой версии достаточно их количества.

## Порядок реализации

1. **Проверить API на реальных аккаунтах.** На одном канале каждой площадки
   проверить получение списка видео, статистики и тестовую публикацию.
   Публикацию выполнять по отдельному согласованию конкретного ролика и канала.
   Зафиксировать права, квоты, обновление токенов, ограничения приложения
   и доступные форматы: обычные видео, Shorts, VK Клипы, Reels.
   Исследование статистики само по себе не подтверждает возможность публикации.
2. **Подготовить контракт плагина и подключение к Shtab.** Реализовать минимально
   необходимые регистрацию плагина, передачу пользователя и проверку доступа к проекту.
   Сейчас контракт описан в `docs/PLAN.md`, но ещё не реализован.
3. **Сделать сквозной путь на одной площадке.** Подключение канала → карточка
   → публикация → внешний статус и ссылка → фоновая статистика → dashboard.
   Первую площадку выбрать по результатам проверки API.
4. **Подключить остальные площадки** через отдельные адаптеры; показывать
   фактические возможности каждого подключения.
5. **Проверить надёжность:** перезапуск фонового обработчика, истечение доступа,
   ограничения API, частичные ошибки и защита от повторной публикации.
6. **Добавить расписание публикаций** и удобства массовой работы.

Особые проверки: расширенная аналитика VK и доступность API Клипов;
для Instagram — профессиональный аккаунт Business/Creator, разрешения приложения
и требования к доступности видеофайла для загрузки площадкой.

## Техническая основа

- Отдельный сервис плагина и собственная БД PostgreSQL; доступ к ядру только по контракту.
- Backend: FastAPI; фоновые задачи: taskiq и Redis; frontend: Web Component.
- Основные сущности: подключение, канал, ролик, файл/вариант, публикация,
  замер статистики, фоновое задание.
- Файлы хранить отдельно от БД. В первой версии — готовые видео и обложки;
  полноценная библиотека ассетов появится позже.
- Токены хранить на сервере в зашифрованном виде, исключить их из логов и ответов frontend.
- Задания переживают перезапуск, учитывают лимиты площадок и повторяются
  с задержкой; длительная обработка не держит открытым запрос браузера.

## Когда первая версия готова

- Пользователь видит свои подключённые каналы в одном месте.
- Может отправить готовый ролик на выбранные площадки с подтверждённой поддержкой API.
- Видит состояние каждой публикации и ссылку на результат.
- Ранее опубликованные видео тоже попадают в dashboard.
- Статистика обновляется без открытого браузера, сохраняет историю и показывает свежесть данных.
- Ошибки видны и допускают безопасный повтор без потери успешных результатов.

## Последующие этапы

1. **Анализ популярности.** Сравнение роликов по площадке, формату и возрасту
   публикации; поиск тем и приёмов, которые дают лучшие результаты.
2. **Идеи и сюжеты.** Предложения тем и сценариев на основе результатов,
   задач компании и выбранной аудитории; утверждение человеком.
3. **Библиотека ассетов.** Исходники, фрагменты съёмок, фотографии, музыка,
   логотипы, озвучки; теги, поиск и привязка к роликам.
4. **Генерация видео.** Сборка из ассетов, генерация недостающих материалов,
   озвучка, субтитры и варианты под площадки. Предпросмотр и утверждение перед публикацией.

Провайдеров генерации и бюджет выбрать на соответствующем этапе.
