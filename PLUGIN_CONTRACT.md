# Контракт плагина Shtab — первая версия

Цель: подключить «Задачи» с Kanban-доской и списком, затем «Заметки».
Плагин — Python-пакет внутри процесса ядра и Web Component в браузере.
Отдельный сервис или контейнер не нужен. Первые плагины — собственные, доверенные.

## Что уже работает

`PluginManager` и UoW сохраняют описание в БД. Роуты `/api/plugins`
доступны только администратору. React получает UI-манифесты через
`GET /api/plugin-ui`, добавляет меню и при открытии страницы загружает ES-модуль.
`GET /api/plugin-assets/{id}/{path}` отдаёт файлы интерфейса вошедшему пользователю.
При установке пакет копируется из `local:...` или клонируется Git, проверяется
манифест, запускается `uv sync` и подключается backend. При старте ядро читает БД
и восстанавливает маршруты установленных пакетов без повторного скачивания.
Если файлы зарегистрированного плагина потеряны, запуск завершается с ошибкой.

## Структура репозитория плагина

```text
manifest.json                 # в корне репозитория
pyproject.toml                # пакет и зависимости
src/shtab_tasks/plugin.py      # точка входа Python
frontend/index.js             # готовый ES-модуль с Web Component
migrations/                   # миграции данных плагина
```

Репозиторий размещаем в `core/plugins/tasks/` (`paths.plugins / plugin.id`).
Python-пакет должен быть установлен в окружение ядра; одной папки
недостаточно. Общие `pyproject.toml`, `uv.lock` и `.venv` находятся в корне Shtab.
Источник `shtab-core = { workspace = true }` задаёт корневой `tool.uv.sources`;
плагину достаточно объявить зависимость `shtab-core` в `project.dependencies`.
Собственный `tool.uv.sources` для ядра в плагин не добавляем.
Исходник `todo/` — локальный шаблон, установленная копия — `core/plugins/todo/`.

## Манифест

Формат соответствует текущим `Plugin` и `PluginIn`:

```json
{
  "id": "tasks",
  "name": "Задачи",
  "version": "0.1.0",
  "url": "https://github.com/OWNER/shtab-tasks",
  "backend_entrypoint": "shtab_tasks.plugin:register",
  "frontend": {
    "entry": "frontend/index.js",
    "pages": [
      {"path": "/plugins/tasks", "element": "shtab-tasks"}
    ],
    "menu_items": [
      {"slot": "sidebar.main", "title": "Задачи", "path": "/plugins/tasks", "order": 20}
    ]
  }
}
```

`id` постоянный и уникальный. `entry` — путь относительно папки плагина.
`pages.path` — маршрут браузера; `menu_items.path` ссылается на него.
`element` — имя, регистрируемое через `customElements.define()`.
`frontend` может быть `null` для плагина без интерфейса.

## Python

- Точка входа — обычная функция `register(app: FastAPI) -> None`.
- Она подключает роутер с префиксом `/api/plugins/tasks` и не выполняет миграции.
- Пользователь определяется зависимостью `CurrentUser` ядра. ID пользователя
  из тела запроса не считается подтверждением его личности или прав.
- Администратор управляет плагинами; обычный вошедший пользователь может
  пользоваться функциями плагина в пределах своих прав.
- Данные плагина имеют собственные модели и миграции. Таблицы ядра напрямую
  не изменяем. Репозитории не вызывают `flush/commit/rollback/close`;
  транзакцией управляет UoW по команде сервиса.
- Конкретное хранилище задач и права доступа согласуем перед реализацией.

## Интерфейс

1. Ядро при запуске читает записи плагинов и вызывает точки входа Python.
2. Отдельный API для вошедшего пользователя возвращает доступные UI-описания.
   Административный `/api/plugins` для этого не используем.
3. React рисует пункты меню сам: `sidebar.main` — основное меню,
   `sidebar.bottom` — нижняя часть; внутри места сортирует по `order`.
4. При открытии страницы React загружает ES-модуль и создаёт указанный элемент.
5. Компонент обращается к своему API через тот же домен с сессией ядра.

JS доступен по `/api/plugin-assets/tasks/frontend/index.js`; API — по
`/api/plugins/tasks/...`. Ядро преобразует относительный `entry` в URL.
Плагин не изменяет DOM меню ядра: он описывает пункты, ядро размещает их.
В текущей версии маршруты страниц точные, без параметров и wildcard.
ES-модуль синхронно регистрирует элементы при импорте. JS, CSS и ресурсы
храним рядом с entry или в его подпапках; относительные импорты работают.
После изменения версии плагина с уже зарегистрированным Web Component
нужно перезагрузить страницу: браузер не умеет отменять `customElements.define()`.

Установка в текущей версии рассчитана на один процесс ядра (один worker).
Удаление записи из реестра пока не выгружает уже импортированный Python-код.

## Готовность первого плагина

Пункт «Задачи» открывает интерфейс; задачу можно создать, изменить и удалить.
Есть переключение «Список / Kanban», смена статуса и сохранение после перезапуска.
Без входа API недоступен.

## MCP

Плагин может объявить в манифесте `"mcp_entrypoint": "shtab_notes.mcp:register_tools"`.
Точка входа принимает `PluginTools` из `shtab_core.mcp_gateway`. Декоратор
`@tools.tool("create", annotations=...)` зарегистрирует `notes_create` для плагина
`notes`. Ядро публикует инструменты всех активных плагинов на `/mcp/` и убирает
их при отключении плагина. Используйте `require_mcp_user_id()` для определения
владельца токена и проверяйте доступ в сервисе перед чтением или изменением данных.

Для Codex выпустите токен через `POST /api/me/mcp-tokens` в Swagger (`/api/docs`)
после входа в Shtab. Токен показывается при создании и действует 30 дней. Задайте
`SHTAB_MCP_TOKEN` в окружении процесса Codex и добавьте подключение:

```powershell
codex mcp add shtab --url http://127.0.0.1:8000/mcp/ --bearer-token-env-var SHTAB_MCP_TOKEN
```

Перезапустите Codex после настройки. Для удалённого подключения укажите HTTPS-адрес
Shtab. Токен можно отозвать через `DELETE /api/me/mcp-tokens/{token_id}`.
Плагин заметок предоставляет `notes_list`, `notes_get` и `notes_create`.
